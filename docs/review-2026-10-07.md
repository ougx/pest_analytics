- **Date:** 2026-10-07
- **Code state:** commit `ffd678a` plus uncommitted work at the time of review (React 18 fix, Observation Conflict page, Residual Analysis pairing fix)
- **Scope:** every registered page, parser and helpers (`utils.py`, `pst.py`, `layout.py`), tests, and the untracked `pest_app/` and `module2/` folders
- **Verification:** items marked "confirmed" were reproduced against `testdata/example_pst.zip`

Tick items off (`[x]`) as they are addressed. Line numbers refer to the code at the time of review and may drift.

## Overall

The analyses are well chosen and build on each other. The pattern of one module per tab, a shared `parse_zip`, and helpers in `pst.py` is easy to extend, and there's a real test suite.

The weaknesses are in four areas:
- **The parser:** several file-name and format assumptions fail silently on real runs.
- **Performance:** every callback re-reads the entire zip.
- **Scientific foundations:** the covariance-based pages ignore regularization.
- **Code duplication:** copy-pasted pages carry the same bugs.

None of the remaining bugs is visible on the example zip, which is why the app looks solid today.

## 1. Bugs (confirmed) — all fixed 2026-10-08 on branch `obs-conflict-and-fixes`

- [x] **1.1 Iterations ≥ 10 are dropped** — [utils.py:160](../utils.py#L160)
  The iteration number is read from the last character only. `case.jco.10` doesn't parse and is skipped; `case.rei.12` would be read as iteration 2. Runs with 10 or more iterations silently lose every iteration from 10 on. **High.**
- [x] **1.2 Regularization rows are dropped** — [utils.py:203](../utils.py#L203)
  Residuals are inner-joined with the observation list, so prior-information (regularization) rows are dropped: 70 rows (groups `regulhk/sy/vk/ss`) in the example. Phi Evolution never shows regularization φ, although its "% excludes regul" logic expects it. Matters for Tikhonov runs.
- [x] **1.3 Numeric `grp*` column in `obs.csv` crashes loading** — [utils.py:150](../utils.py#L150)

## 2. Scientific and method issues

- [ ] **2.1 Covariance ignores regularization**
  Parameter Correlation, Residual Analysis leverage and Observation Similarity use (JᵀQJ)⁻¹ without regularization. In highly parameterized runs JᵀQJ is singular.
  - `np.linalg.inv` rarely raises an error; it returns huge, meaningless numbers, so the `pinv` fallback almost never runs ([parcor.py:97](../module/parcor.py#L97)).
  - Correlations for parameters with no information in the data are then noise.
  - **Fix:** include the prior-information rows (needs the parser to read `* prior information`, see 1.2), or use SVD truncation.
- [x] **2.2 Identifiability cutoff far too loose** — [parident.py:98](../module/parident.py#L98)
  Compares *singular-value* ratios to 5e-7. PEST's EIGTHRESH is an *eigenvalue* ratio (eigenvalue = singular value²), so the equivalent singular-value cutoff is about 7e-4. As written, nearly every parameter looks identifiable.
- [ ] **2.3 "Parameter variance" on Phi Evolution** — [phiupdate.py:112](../module/phiupdate.py#L112)
  Variance of (p − p₀)/p₀ across all non-fixed parameters, including tied ones.
  - For log parameters, log₁₀(p/p₀) is the meaningful measure.
  - Subtracts `par.parval0` by row position rather than by parameter name; wrong if the `.par` and `.pst` list parameters in different orders.
- [ ] **2.4 Inconsistent weight handling**
  Phi Evolution, Residual Analysis and Observation Conflict let the user choose `weight_orig`; Parameter Sensitivity, Parameter Correlation, Observation Similarity and Identifiability always use `weight`.
- [ ] **2.5 Scatter / Time Series statistics**
  Include zero-weight observations unless "Hide" is selected, and "R²" is corr², not Nash–Sutcliffe efficiency. Labels should say so.
  *2026-10-08:* statistics now always exclude zero-weight targets (table header says "weight > 0"). The R² label is still open.
- [ ] **2.6 Only PEST_HP file names are read**
  `.jco.N`, `.rei.N`, `.hp`. PEST++ output (`.jcb`, `case.N.rei`, etc.) isn't recognized. Fine if intended, but the Upload page should say so.

## 3. Performance and architecture

- [x] **3.1 The zip is re-read on every callback**
  Loading data triggers about 15 callbacks; several parse the full zip including all Jacobians, and some do it twice (`update_groups` and `update_weights` each re-parse). Every Plot button press parses again. The example takes 0.3 s per parse; a real model with a 5000 × 1000 Jacobian and 10+ iterations turns each click into seconds and hundreds of MB of memory per request.
- [x] **3.2 Uploads round-trip through the browser**
  A drag-and-drop file is kept in the browser as base64 and sent back to the server with every callback. A 200 MB zip means about 270 MB uploaded on every click.

**Fix for both:** parse once on the server, cache the result keyed by file path or a hash of the content, and keep only that key in the browser.

*Fixed 2026-10-08* (`utils.py`):
- Uploads are saved once on the server under a content hash (`PEST_UPLOAD_DIR`, default `%TEMP%\pest_analytics_uploads`, files older than 7 days removed); the browser keeps only `{"filename", "upload": key, "pestpath"}`.
- `parse_zip` serves parsed results from an in-memory cache (`PEST_CACHE_SIZE`, default 4 entries = 2 datasets), keyed by path + modification time + size, so a re-run zip is re-read. Jacobians are only loaded when a page needs them; concurrent callbacks wait for one parse.
- Measured on the example zip: zip reads during a data load 15 → 2 (5.0 s → 2.75 s for the load callbacks); callback requests after an upload ≤ 1.7 KB instead of the full 36 MB each.

## 4. Deployment and security

- [ ] **4.1 Third-party scripts copied from the Mantine docs site** — [app.py:30](../app.py#L30)
  Google Analytics with *their* tracking ID (`G-4PJELX1C4W`), an ad-network script (ethicalads), and Russian/French date locales. Users' visits are reported to someone else's analytics, and these scripts fail on an offline network. Five of the seven stylesheets are for Mantine add-on packages (dates, charts, carousel, etc.) the app never uses.
- [ ] **4.2 Debug server exposed to the network** — [app.py:117](../app.py#L117)
  `python app.py` runs with `debug=True` on `0.0.0.0`, exposing Flask's interactive debugger (PIN-protected) to other machines. Use `127.0.0.1` for debug runs; waitress is unaffected.
- [ ] **4.3 Server path field**
  Any user on the network can open any zip the server account can read. Acceptable on an internal network, but worth knowing.
- [ ] **4.4 No pinned `requirements.txt`**
  The blank-page React problem came from an unpinned Dash and Mantine-components combination. Versions at review time: dash 2.18.2, dash-mantine-components 0.15.3, plotly 6.9.0, pandas 2.3.3, numpy 2.2.6, Flask 3.0.3, waitress 3.0.2.

  - Phi Evolution redraws automatically; every other page needs a button.

- [x] **5.4 "Iteration" is ambiguous** — on Jacobian-based pages it means the Jacobian iteration, which pairs with the previous iteration's parameters. Label it consistently.
  *Fixed 2026-10-08:* Jacobian pages say "Jacobian Iteration" with a note on which files are used; both Sensitivity pages name series "Jacobian N" and color them by iteration N-1 (dropping the placeholder "Iter 0" line).

  *Fixed 2026-10-08:* the small data reference is saved in the browser tab's sessionStorage and restored on page load (closing the tab still clears it). Done with clientside callbacks because dcc.Store's session storage was reset to its initial value at start-up.
- [x] **5.7 Empty states** — before plotting, each page shows a blank chart with its message as the title. A plain message would look cleaner.
  *Fixed 2026-10-08:* every placeholder and error message is a plain centred message without axes (`plotting.message_figure`), with consistent "Load data, then click …" wording.
- [x] **5.8 Small details**
  - Footer positioned with a hard-coded `padding-left: 205px`.

  - SSP&A logo loaded from sspa.com rather than stored in `assets/`.

  *2026-10-08:* footer is a single status line without the hard-coded offset (upload help moved to the Upload page); header and browser tab both say "PEST_HP_ANALYTICS"; the logo is served from `assets/`.
- [x] **5.9 No data export** — charts can be saved as PNG, but there's no CSV download of computed tables (tension, identifiability, correlations).
  *Fixed 2026-10-08:* every plot has a "Download data (CSV)" button (`layout.graph`, `plotting.figure_to_frame`): heatmaps download as their matrix, tables as their cells, Sankeys as their links, other charts as one row per point.
